# تحلیل دیدگاه‌های دیجی‌کالا با ترنسفورمر

این پروژه از متن فارسی دیدگاه‌های کاربران دیجی‌کالا استفاده می‌کند تا برای هر دیدگاه، دو پیش‌بینی انجام دهد:

1. **آیا محصول توصیه می‌شود؟** (`recommended`، `not_recommended` یا `no_idea`)
2. **امتیاز محصول در چه بازه‌ای قرار می‌گیرد؟** (`low`، `medium` یا `high`)

مدل فقط متن دیدگاه را دریافت می‌کند؛ یعنی اطلاعات دیگری مثل نام محصول یا امتیاز ثبت‌شده، ورودی مدل نیست. بازه‌های امتیاز هم به این شکل تعریف شده‌اند:

- `low`: امتیاز کمتر از ۲٫۵
- `medium`: امتیاز از ۲٫۵ تا کمتر از ۴
- `high`: امتیاز از ۴ تا ۵

## نمای کلی پروژه

مسیر کار از داده خام شروع می‌شود و در نهایت به یک API قابل اجرا با Docker می‌رسد:

1. داده‌های خام بررسی و متن دیدگاه‌ها نرمال‌سازی می‌شوند.
2. داده‌ها با توجه به شناسه محصول به بخش‌های train، validation و test تقسیم می‌شوند.
3. یک مدل پایه با TF-IDF و Logistic Regression آموزش داده می‌شود.
4. سه مدل زبانی ParsBERT، XLM-RoBERTa و mBERT در یک آزمایش اولیه با هم مقایسه می‌شوند.
5. مدل ParsBERT به‌صورت نظارت‌شده آموزش داده می‌شود.
6. یک آزمایش نیمه‌نظارتی با استفاده از برچسب‌های تولیدشده توسط مدل انجام می‌شود. در این مرحله فقط پیش‌بینی‌هایی با احتمال حداقل ۰٫۹۰ پذیرفته می‌شوند.
7. در پایان، هر سه مدل از طریق API و داخل یک کانتینر Docker قابل استفاده‌اند.

## ۱. پیش‌نیازها و آماده‌سازی پروژه

برای اجرای کامل پروژه به این موارد نیاز دارید:

- Python و محیط اجرای Jupyter یا VS Code
- فضای ذخیره‌سازی و حافظه کافی برای داده‌ها، مدل‌ها و خروجی آزمایش‌ها

- Docker Desktop برای اجرای API
- Git LFS برای دریافت وزن مدل‌هایی که در مخزن Git ذخیره شده‌اند

> دستورهای نصب زیر برای Windows PowerShell نوشته شده‌اند.

### دریافت پروژه و نصب وابستگی‌ها

ابتدا وارد پوشه اصلی پروژه شوید و دستورها را به‌ترتیب اجرا کنید:

```powershell
git lfs install
git lfs pull
py -3.14 -m venv .project_env
.\.project_env\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

این دستورها به‌ترتیب Git LFS را فعال می‌کنند، فایل‌های حجیم مخزن را دریافت می‌کنند، یک محیط مجازی می‌سازند و وابستگی‌های پروژه را نصب می‌کنند.

### باز کردن نوت‌بوک‌ها

نوت‌بوک‌ها را می‌توانید با افزونه Jupyter در VS Code یا با محیط Jupyter باز کنید. هنگام اجرا، kernel مربوط به محیط `.project_env` را انتخاب کنید.

نوت‌بوک‌های محلی را از ریشه پروژه یا پوشه `src` اجرا کنید. همچنین، پیش از نصب وابستگی‌ها سازگاری نسخه‌های نوشته‌شده در `requirements.txt` را با سیستم و نسخه Python خود بررسی کنید.

**نکته:** اجرای آموزش‌ها و ممیزی کل داده‌ها ممکن است زمان‌بر باشد و به فضای ذخیره‌سازی و حافظه کافی نیاز دارد.

## ۲. دریافت و قرار دادن دیتاست

برای اجرای پایپ‌لاین، به فایل دیدگاه‌های دیجی‌کالا نیاز دارید.

1. وارد [صفحه دیتاست دیدگاه‌های دیجی‌کالا در Hugging Face](https://huggingface.co/datasets/RadeAI/Digikala_comments_products/tree/main) شوید و فایل `digikala-comments.csv` را دانلود کنید.
2. اگر ترجیح می‌دهید، می‌توانید آرشیو `digikala.rar` را دریافت و فایل نظرات را از داخل آن استخراج کنید.
3. فایل CSV را در مسیر زیر قرار دهید:

```text
Transformer-Project/
└── data/
    └── raw_data/
        └── digikala-comments.csv
```

نام پوشه اصلی پروژه می‌تواند هر چیزی باشد؛ اما نام فایل و مسیر داخل پروژه باید دقیقاً همین باشد:

`data/raw_data/digikala-comments.csv`

**توجه:** فایل موردنیاز، خود فایل `digikala-comments.csv` است؛ آرشیو RAR را مستقیماً داخل `raw_data` قرار ندهید. فایل محصولات نیز برای این پایپ‌لاین لازم نیست.

### مرحله ۱: بررسی داده و پیش‌پردازش

نوت‌بوک `src/preprocess.ipynb` را باز کنید و سلول‌ها را به‌ترتیب اجرا کنید.

این نوت‌بوک با کمک اسکریپت `src/eda_audit.py` داده خام را بررسی می‌کند، متن دیدگاه‌ها را نرمال‌سازی می‌کند و داده‌ها را با درنظرگرفتن شناسه محصول به سه بخش train، validation و test تقسیم می‌کند.

برای آزمایش نیمه‌نظارتی، بخشی از برچسب‌های داده train نیز با یک قاعده ثابت پنهان می‌شوند.

پس از اجرای موفق، فایل‌های زیر در این مسیر ساخته می‌شوند:

```text
data/clean_data/split_body_cleaned/
├── train_supervised.csv
├── train_pseudo_unlabeled.csv
├── natural_unlabeled.csv
├── validation.csv
├── test.csv
├── mask_manifest.csv
└── split_manifest.json
```

کاربرد فایل‌های مهم:

- `train_supervised.csv`: داده‌های آموزشی دارای برچسب
- `train_pseudo_unlabeled.csv`: داده‌هایی که برچسبشان برای آزمایش نیمه‌نظارتی پنهان شده است؛ این فایل فقط شناسه و متن دارد.
- `natural_unlabeled.csv`: داده‌های بدون برچسب
- `validation.csv` و `test.csv`: داده‌های اعتبارسنجی و آزمون
- `mask_manifest.csv`: اطلاعات لازم برای بررسی کیفیت برچسب‌های مصنوعی پس از آموزش
- `split_manifest.json`: اطلاعات مربوط به تقسیم داده‌ها

گزارش‌های ممیزی نیز در مسیر `reports/preprocess/` ذخیره می‌شوند.

**نکته درباره اجرای دوباره:** اگر تمام خروجی‌های موردنیاز از قبل وجود داشته باشند، نوت‌بوک از همان‌ها استفاده می‌کند. اما اگر فقط بخشی از خروجی‌ها موجود باشد، اجرا با خطا متوقف می‌شود.

### مرحله ۲: آموزش مدل پایه TF-IDF

بعد از آماده شدن داده‌ها، نوت‌بوک `src/tf_idf.ipynb` را از ریشه پروژه یا پوشه `src` اجرا کنید.

این نوت‌بوک برای هرکدام از دو هدف پروژه، یک مدل TF-IDF به‌همراه Logistic Regression آموزش می‌دهد.

خروجی‌ها در این مسیرها ذخیره می‌شوند:

- مدل‌ها: `models/tf_idf/`
- گزارش‌ها: `reports/tf_idf/`

تنظیم پیش‌فرض `LIMITS` از کل splitها استفاده می‌کند.

در سلول‌های پایانی نوت‌بوک، مقایسه با ParsBERT انجام می‌شود. برای اجرای این بخش، دو فایل زیر باید در مسیر مشخص‌شده وجود داشته باشند:

```text
reports/parsbert_finetuning/reports/reports/
├── run_config.json
└── final_metrics.csv
```

اگر این گزارش‌ها را ندارید، ابتدا آموزش و ارزیابی نظارت‌شده ParsBERT را در مرحله ۴ انجام دهید و فایل‌های گزارش را در همین مسیر قرار دهید.

### مرحله ۳: مقایسه سه ترنسفورمر

پس از آماده شدن splitها، نوت‌بوک `src/transformers_competition.ipynb` را از ریشه پروژه یا پوشه `src` اجرا کنید.

در این آزمایش سه مدل زیر بررسی و با هم مقایسه می‌شوند:

- ParsBERT
- XLM-RoBERTa
- mBERT

دریافت tokenizer و checkpointهای این مدل‌ها به اینترنت نیاز دارد.

**محدودیت این آزمایش را در نظر داشته باشید:** تنظیمات فعلی برای مقایسه اولیه از یک نمونه ثابت با حداکثر ۳۰۰۰ ردیف و فقط یک epoch استفاده می‌کنند. بنابراین نتایج این مرحله را نباید با نتایج آموزش کامل ParsBERT در مرحله بعد یکسان در نظر گرفت.

3. هر زمان درخواست شد، دسترسی Colab به Google Drive را تأیید کنید.

مسیر پیش‌فرض پروژه در کد این است:


اگر پوشه پروژه را با نام یا مسیر دیگری ساخته‌اید، مقدار `PROJECT_DIR` را متناسب با آن تغییر دهید.

#### ۴.۳. تنظیمات آموزش و محل ذخیره مدل

تنظیمات فعلی حداکثر دو میلیون ردیف از داده train را با نمونه‌گیری ثابت انتخاب می‌کنند. سپس مدل برای پیش‌بینی هر دو خروجی پروژه آموزش می‌بیند.

این مرحله ممکن است زمان‌بر باشد و فضای زیادی در Google Drive مصرف کند.

- checkpointهای بازیابی آموزش در مسیر `outputs/parsbert_finetuning/checkpoints/` ذخیره می‌شوند.
- اگر جلسه Colab قطع شد، سلول‌ها را از ابتدا اجرا کنید تا فرایند بازیابی به‌شکل سازگار انجام شود.
- مدل نهایی در مسیر زیر ذخیره می‌شود:

```text
MyDrive/digikala-transformer/outputs/parsbert_finetuning/artifacts/
```

### مرحله ۶: انتقال خروجی‌های Colab به سیستم محلی

بعد از پایان سلول‌های ذخیره artifacts، **محتوای کامل** دو پوشه زیر را از Google Drive دانلود کنید و در مسیرهای محلی متناظر قرار دهید. نام فایل‌ها و ساختار پوشه‌ها را تغییر ندهید.

| مبدأ در `MyDrive/digikala-transformer/outputs/` | مقصد در پروژه محلی |
| --- | --- |
| `parsbert_finetuning/artifacts/` | `models/parsbert_finetuning/artifacts/` |
| `semi_supervised_v1/artifacts/` | `models/semi_supervised/artifacts/` |

در نهایت، ساختار پوشه `models/` باید برای اجرای سرویس به شکل زیر باشد:

```text
models/
├── tf_idf/
│   ├── recommendation_status.joblib
│   └── rating_band.joblib
├── parsbert_finetuning/artifacts/
│   ├── model.safetensors
│   ├── model_metadata.json
│   └── tokenizer/                  # تمام فایل‌های tokenizer
└── semi_supervised/artifacts/
    ├── model.safetensors
    ├── model_metadata.json
    ├── tokenizer/                  # تمام فایل‌های tokenizer
    └── encoder_config/config.json
```

چند نکته مهم پیش از اجرای API:

- فایل‌های مدل TF-IDF با اجرای محلی نوت‌بوک TF-IDF ساخته می‌شوند.
- فایل `encoder_config/config.json` برای مدل نیمه‌نظارتی لازم است؛ کد فعلی برای بارگذاری هر دو ترنسفورمر به آن نیاز دارد.
- پوشه‌های `reports/` و `plots/` هر آزمایش را نیز برای نگهداری نتایج دانلود کنید.
- برای اجرای بخش مقایسه در نوت‌بوک TF-IDF، گزارش‌های ParsBERT را در مسیری که در مرحله ۲ گفته شد قرار دهید.
- checkpointهای موقت برای اجرای API لازم نیستند.

اگر مدل‌های آموزش‌دیده را از Git دریافت کرده‌اید، پیش از اجرای سرویس بررسی کنید که Git LFS فایل‌های واقعی `model.safetensors` را دریافت کرده باشد. حجم وزن‌ها در مجموع حدود ۱٫۳ گیگابایت است.

**نکته مهم:** API فعلی هر سه مدل را هنگام شروع سرویس بارگذاری می‌کند. بنابراین اگر حتی یکی از فایل‌های ضروری وجود نداشته باشد، سرویس شروع نخواهد شد.

## ۴. اجرای API با Docker

اگر مدل‌ها و فایل‌های موردنیاز را طبق مرحله قبل آماده کرده‌اید، برای اجرای API دیگر نیازی به دانلود دیتاست خام یا آموزش دوباره مدل‌ها ندارید.

### ۴.۱. بررسی Docker

ابتدا Docker Desktop را نصب و اجرا کنید. سپس در PowerShell دستور زیر را بزنید:

```powershell
docker version
```

باید اطلاعات هر دو بخش **Client** و **Server** نمایش داده شود. اگر هر دو بخش نمایش داده شدند، Docker آماده استفاده است.

### ۴.۲. ساخت ایمیج

از ریشه پروژه دستور زیر را اجرا کنید:

```powershell
docker build -t digikala-review-api .
```

در زمان ساخت ایمیج، `Dockerfile` ایمیج پایه Python را از Amazon ECR و وابستگی‌های `requirements-api.txt` را از mirror تنظیم‌شده برای pip دریافت می‌کند. بنابراین سیستم باید به هر دو منبع دسترسی شبکه داشته باشد.

فایل `.dockerignore` اجازه نمی‌دهد داده‌ها و مدل‌ها وارد فرایند ساخت ایمیج شوند.

### ۴.۳. اجرای کانتینر

پس از ساخته شدن ایمیج، این دستور را از ریشه پروژه در PowerShell اجرا کنید:

```powershell
docker run --rm -p 127.0.0.1:18080:8000 -v "${PWD}/models:/app/models:ro" --name digikala-api digikala-review-api
```

این دستور:

- پوشه محلی `models` را به مسیر `/app/models` داخل کانتینر متصل می‌کند.
- اتصال پوشه مدل‌ها را فقط‌خواندنی (`ro`) نگه می‌دارد.
- پورت محلی `18080` را به پورت `8000` داخل کانتینر وصل می‌کند.
- از `--reload` استفاده نمی‌کند.

سرویس فعلی با CPU اجرا می‌شود. پس از اجرای دستور، منتظر نمایش پیام زیر بمانید:

```text
Application startup complete
```

اگر پورت `18080` قبلاً استفاده شده و در دسترس نیست، عدد سمت چپ `:8000` را به یک پورت آزاد تغییر دهید.

### ۴.۴. ارسال درخواست به API

پس از بالا آمدن سرویس، آدرس زیر را در مرورگر باز کنید:

```text
http://127.0.0.1:18080/docs
```

این صفحه، مستندات تعاملی API است.

برای آزمایش پیش‌بینی:

1. مسیر `POST /predict` را باز کنید.
2. روی **Try it out** کلیک کنید.
3. متن دیدگاه و مدل موردنظر را در درخواست قرار دهید.
4. درخواست را اجرا کنید.

برای نمونه:

```json
{
  "text": "کیفیت محصول خوب بود اما بسته‌بندی ضعیف بود",
  "model": "semi_supervised"
}
```

مقدار `model` می‌تواند یکی از این سه گزینه باشد:

- `tfidf`
- `transformer`
- `semi_supervised`

پاسخ API شامل متن نرمال‌شده و برچسب و احتمال مربوط به هر دو خروجی است.

همچنین مسیر `GET /health` برای بررسی وضعیت برنامه در دسترس است.

برای متوقف کردن کانتینر، به ترمینالی که دستور اجرا در آن فعال است برگردید و `Ctrl+C` را بزنید.
